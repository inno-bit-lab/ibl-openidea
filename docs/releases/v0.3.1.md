# IBLOpenIdea 0.3.1

Draft release notes. Candidate build and desktop acceptance are still pending.

IBLOpenIdea 0.3.1 brings in OpenIDEA v0.1.31 (`06109aae`), with the fork's brand, profile migration, Italian interface and agent/VCS workflows.

## Before you upgrade

- Projects open in Restricted Mode until you trust them. Reading and editing remain available; project-controlled execution waits for trust. This includes project Git executables, filters and hooks, configured terminal startup commands, run configurations and agents. Trust is not an OS sandbox: a terminal you open can still execute commands.
- If there is no `project-trust.json`, your recent projects become trusted on the first start. This also applies to profiles copied during migration. Existing trust decisions are kept.
- Remote development now uses protocol 2. Older `openidea-server` versions are incompatible; the app downloads the matching server.
- Windows ARM64 and Linux ARM64 builds are added. An x64 installation on an ARM machine keeps updating to x64 builds. To switch architecture, install the native ARM64 build manually. ARM installers and updater behaviour still need native qualification.

## Languages, projects and deployment

- Richer JVM project icons and core Go workflows.
- CMake targets can run, and rename works through file aliases. Tomcat deployment uses the WAR from the selected Maven module. Java language-server access restrictions appear as warnings.
- The Java debugger shows startup progress and supports cancellation. Services shows debug-session output and state.
- Deploy to a local or mounted folder. The server picker shows only the servers that cover the selected paths. Deleting a folder on the server (Delete from Server, or the automatic remote delete after a local delete) keeps excluded entries such as `.git` and any mapped folders inside it. Selecting a folder also covers the mappings inside it.

## Editor, search and shelf

- Import and export IntelliJ `.icls` editor colour schemes.
- Open in-file Find results in the Find window, search console output, and use the focused folder for Find in Files.
- Shelved changes have per-file views and actions. Changes to `file.bin` and `b/file.bin` can coexist without losing a sibling's change.
- Preview layout controls are in the tab strip, the scratch-language search field is visible, and a terminal keeps focus after its context menu.
- External file changes synchronize when the IDE window regains focus. This is enabled by default; Settings has an opt-out.
- Transparent native-to-ascii for `.properties` files remains off by default. When enabled, escapes for `=`, `:`, `#`, `!`, whitespace and backslash remain visible as escapes, so saving does not change keys or turn lines into comments.
- Console search handles an empty match before an emoji without hanging.

## Windows, Linux and ARM

- On Windows, cancelling or closing an agent task, probe or commit suggestion also ends processes started by that agent, including dev servers, watchers and build daemons. Processes that break away from the Windows job are excluded. Trust revocation uses the same teardown. Unix behaviour is unchanged.
- On Windows, the first start after updating from v0.2.x shows a progress window while IBLOpenIdea copies your profile. It appears once and closes by itself; do not end the app while it is shown. macOS and Linux keep their current behaviour.
- Linux gets a frameless title bar. Settings placement is constrained to the work area on Windows and Linux; scaled and secondary-monitor desktop checks are still pending. A new option merges the main menu into the toolbar; keyboard focus stays in the menu when it collapses to the hamburger.
- On Windows ARM64, tool and agent resolution prefers native executables, then npx, uvx and emulated x64. Windows 11 on Arm emulates both x86 and x64 apps; Windows 10 on Arm emulates only x86 apps. This documents the OS capability, not a tested IBLOpenIdea ARM installation. [Microsoft documentation](https://learn.microsoft.com/en-us/windows/arm/apps-on-arm-x86-emulation).

## Agents and commit suggestions

- The agent catalog and custom agent arguments remain available from Welcome and Restricted Mode. These settings only touch your user profile.
- Commit Suggest requires a trusted project. Revoking trust cancels a running suggestion, shows the refusal immediately and keeps the draft. Closing the project also cancels its running suggestion. A late answer cannot replace the draft or interfere with a newer request after re-trust.
- Commit suggestions require a valid structured response and a completed agent turn. Replies that are invalid, failed, cut short or missing a stop reason show an error and keep your draft. A valid structured response does not guarantee that the suggested message describes the changes correctly.

## Italian

The Italian interface includes the new project-trust controls and explanations. Welcome navigation and Find in Files prompts and result summaries are translated, including locale-specific number formatting. The terms diff, task, workspace, breakpoint, watchpoint, timeline, effort, thinking, shelve, stash and stage stay in English. Existing agent-engine refusal, cancellation and stop errors can still appear in English; the two structured-answer errors are translated.

## Known limitations and pending checks

- Antigravity 1.4.5 can time out during ACP initialization after 30 seconds on some machines. This was also observed without the Windows teardown change.
- The `pi-acp` 0.0.34 adapter can report a failed prompt as a normal end of turn, hiding provider errors such as exhausted credit. No fixed adapter version is available yet.
- In the Italian interface, some menu, list and dialog names that screen readers announce are still in English.
- Windows Installed apps can keep showing the previous version after an in-app update. The cause is under investigation.
- Trusting a project while it is being revoked or closed can leave agent access out of step with the project's trust. A separate race between starting an agent task and revoking trust is also still open.
- If Windows cannot place an agent in its Job Object, cleanup has to go through the agent's own process, so processes the agent started can keep running if it has already exited.
- The project environment and selected Git executable remain process-wide. A restricted window's terminal can therefore see another trusted window's environment.
- PATH includes only installed tool directories, but arbitrary long Windows PATH values can still exceed cmd.exe's 8,191-character limit. Language servers and debuggers installed in Settings are available on the next file open; terminals, run configurations and agents need an app restart to see newly installed tools. A warning records a PATH still over the limit.
- If an earlier profile copy failed, cleanup on the next start has no progress window. Migrated files may also retain absolute paths into the old profile, which is kept.
- Candidate qualification still needs the migration dialog's appearance, focus and scaling; Italian merged menus and real controls; Settings on scaled or secondary monitors; the real trust prompt and disabled Suggest action; native Codex revoke with process-tree and temporary-directory cleanup; trusted/restricted/revoked terminal PATH checks; a real remote host on protocol 2; commit suggestions with Antigravity; and ARM install, start and updater checks. These checks are still pending, and each platform's result will be recorded separately.
