## 3. Solution design

See spec 5.1 to 5.6. Interfaces fixed here:

- Managed agents directory (lint finding 4, rev-claude):
  - `ide_agent::AgentPaths.managed_agents_dir: Option<PathBuf>` and `ide_host::HostConfig.managed_agents_dir: Option<PathBuf>`, kept as a field on `Host` (destructured in `Host::new`, `crates/ide-host/src/lib.rs`).
  - `src-tauri/src/state.rs` sets it to `app.path().app_local_data_dir()?.join("acp-agents")`, so it follows MT-C's identifier change; `openidea-server` (`crates/ide-host/src/bin/server.rs`) sets `<server home>/data/acp-agents`.
  - It reaches the discovery as an explicit parameter along the existing call chain: `resolve_executable` and the functions that call it (`installed`, `resolve_spawn`), and their callers (the connector, `providers_from` and `set_custom_args_in` in `crates/ide-agent/src/lib.rs`, and `crates/ide-host/src/ops/agent.rs`). Update the test call sites (`crates/ide-agent/src/tests.rs`, `crates/ide-host/tests/rpc.rs`).
- `fn agy_search_roots(managed: Option<&Path>, home: Option<&Path>, exe_dir: Option<&Path>) -> Vec<PathBuf>` in `provider.rs`: pure; it returns base roots, including the current user's `JetBrains` parent directories. The enumeration of JetBrains subdirectories stays in `find_agy_acp_server`, which is not pure. No `C:\Users` walk, no hard-coded identifier.
- `fn restrictive_mode(options: &[AgentConfigOption]) -> Result<String, String>` in `crates/ide-agent/src/lib.rs`: finds the option whose `id` or `category` is `mode` and returns the first of `read-only`, `read_only`, `default` among its values. It returns `Err` naming the available values when there is no mode option or no allowlisted value.
- How `complete` uses it (lint findings 1 to 3):
  - It is applied inside `ask()`, after `session/new` and the drained `config_updates`, to the options the agent reported. It never falls back to `known_config`.
  - Caller choices whose `id` or `category` is `mode` are dropped before the mode is applied, so the IPC and RPC callers of `agent_complete` cannot override it.
  - If setting the mode fails, `ask()` returns `Err` before `session/prompt`; today it only logs a failed `session/set_*` and prompts anyway.
  - The read-only error is returned as is and not passed through `describe_error`. Its exact text: `<agent name> cannot run read-only (modes: <values>). Choose Claude, Codex or Antigravity for commit suggestions.`
  - `complete` logs one `info` line with the agent id, the mode chosen and the temporary cwd (spec A3).
- `complete` runs in `std::env::temp_dir()/ibl-suggest-<uuid>`, created empty and removed after the call; a removal failure is logged, not returned.
- New command `vcs_ignored() -> Vec<FileStatus>` (ignored entries only): `crates/ide-host/src/ops/vcs.rs` (`pub async fn ignored`), registered in `crates/ide-host/src/rpc.rs` next to `vcs_status` and as a Tauri command in `src-tauri/src/commands/vcs.rs` plus `collect_commands!` in `src-tauri/src/commands/mod.rs`. `vcs_status` returns `repos.status()` again.
- `deleteInRepos(name, roots, opts?: { confirm?: boolean })`, `deleteRemoteInRepos(name, roots, opts?)`, `deleteRemoteBranch(name, repo, opts?)`: `confirm` defaults to `true`.
- `CustomAgent`: `command` becomes `Option<String>` (`serde(default)`), new `extra_args: Vec<String>` (`serde(default, skip_serializing_if = "Vec::is_empty")`). `deny_unknown_fields` stays.
  - Spawn args are the file's `args` (the built-in's `args` when the file has no `command`) followed by `extra_args`.
  - A non-built-in id without `command` is skipped with a `warn` log naming the file: `load` has no error channel.
  - A v0.2 file whose `args` do not start with the built-in's args stays an explicit override.
- `cherryPick(commits: LogCommit[])` (`LogCommit` in `src/features/vcs/logStore.ts` carries `repo`; `Commit` does not). Update its callers (`src/features/vcs/CompareBranches.tsx:801`, `src/features/vcs/historyActions.tsx:265`). `GitOperationOptions.repo?: string | null`; `runGitOperation` uses `opts.repo ?? currentRepo()` everywhere it uses the repository today (`ops.ts:397` already passes one to `vcsOperation`).
