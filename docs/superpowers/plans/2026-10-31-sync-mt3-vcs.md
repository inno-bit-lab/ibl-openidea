## 3. Solution design

- **Backend.** A single `status_with(r: &Repo, include_ignored: bool)` in `crates/ide-vcs/src/status.rs` built on upstream's `status()`; gix `emit_ignored(CollapseDirectory)` only when `include_ignored`; `status()` calls it with `false`. `Repo::status_with_ignored` in `lib.rs`; `ops::vcs::ignored` in `crates/ide-host/src/ops/vcs.rs`; `vcs_ignored` in `rpc.rs`; the Tauri side (`src-tauri/src/commands/vcs.rs`, `commands/mod.rs` after MT-2's two lines) and the `vcsIgnored` binding only after the MT-2 rebase (Task 7). `roots.rs`: port the fork's `Repos::status_with_ignored(include_ignored)` aggregator (port map 1.4) on upstream's loop (roots.rs:156-169, which calls `repo.status()` and drops only untracked nested roots), so ignored nested roots are not listed twice while ignored files inside child repositories stay visible; re-apply `has_direct_child_repo` and the ancestor rule inside upstream's file, and make `enclosing()` empty for a folder of repositories. `history.rs`: tolerant tips, so a branch missing in one repository does not fail the log. `refs.rs`: tolerant ahead/behind.
- **Log and branches.** BranchesPanel UX (repo tags, side toolbar, Manage Remotes, Update, New Branch) on `branchesByRepo`; `buildMultiRepoBranchTree` in `branches.ts` keyed by repository root; multi-repo `commonBranchMenu` (Update, Push, Checkout across repos, Compare with Current, Show Diff with Working Tree, Delete); `updateInRepos`, `deleteInRepos`, `deleteRemoteInRepos` with one confirmation (`2703f67`). Multi-repo CommitDetails and the Log/Console tabs where upstream lacks them. The fork's Roots multi-filter is dropped in favour of upstream's Repository filter (GitLog.tsx:688). `computeMultiRepoGraph` is dropped: upstream lays out with `graphCommit` (multiRoot.ts:8).
- **Dialogs and remote ops.** `RepoSelect`/`useDialogRepo` in Pull, Merge, Rebase, Manage Remotes and Worktrees, inside upstream's `gitMenuDialogs.tsx` (which still uses `currentRepo()`, gitMenuDialogs.tsx:112, :218). Remotes dialog grouped by repository. Stash gets the picker (unstash already takes `repo`, changeOps.tsx:395). `summarizeRepoError`, `formatRemoteFailures` and "View in Console" in `ops.ts`. `UpdateTarget` (repo or repos) on upstream's `updateProject`; Push scoped to one repository or a subset on upstream's resizable `MultiPushDialog`. Not ported: per-repo cherry-pick (selection is confined to one repository, logStore.ts:501-526; operations.tsx:246) and the Tag/Reset repo picker.
- **History and compare.** `FileHistory.tsx` becomes `SelectionHistory.tsx` with only `sliceLineRange`, `mapRangeToOlder`, `buildSelectionRevisions`, `resolveSelectionTarget`, `showSelectionHistory`, `SelectionHistoryDialog` and `chooseFileRevision`. `FileHistoryView` goes, since upstream's `openLogTab("history")` covers it (logStore.ts:263, actions.tsx:428, :443). Actions `vcs.showHistoryForSelection` and `vcs.showCurrentRevision`; `vcs.compareWithRevision` dropped (upstream "Compare with Branch or Revision…", actions.tsx:322). `DiffEditor` `headerContent`, `cm.ts` `viewerBase({ firstLine })`, `diffInput.ts` `firstLine` and `ignored` only. `CompareBranches.tsx`: the fork's two-pane editor (`COMPARE_BRANCHES_KIND`) rebased on `RepoCommit`; upstream's `showCompareBranches(branch)` signature extended with an optional repo or repos. `menu.rs`: add only "Show History for Selection…" (upstream already has `vcs.showHistory`, menu.rs:667).
- **Commit view.** View Options keep upstream's Group By Directory and Repository (CommitView.tsx:438, changes.test.ts:73) and add Module grouping and Show Ignored Files. The ignored group is loaded only through `vcsIgnored` while the option is on. The changes count leaves ignored entries out. Subtree decoration for `relPath` ending in `/`. Settings › Version Control Directory Mappings lists every Git root.
- **Suggest button.** In `CommitMessageField` (CommitView.tsx:687), so the modal Commit dialog gets it too. It uses `commitSuggest.ts` (`buildSuggestPrompt`, `cleanSuggestion`, `buildSuggestConfig`, `suggestCommitMessage`), `commands.agentComplete` and `CommitSettings.suggest*` from MT-2.
- **Shared UI.** `.dialog` max size clamped to the viewport minus 48px with a scrollable message body; `Tree.tsx` `title` on the detail span; `Tree.module.css` `.label` rule only if labels still truncate wrongly with upstream's `.wideRow` (Tree.module.css:57); multi-line notification balloons (`Notifications.module.css`, `Feedback.module.css`).
