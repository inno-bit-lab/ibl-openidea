# D1 Visible Feedback During the Profile Migration: Implementation Plan (v0.3.1)

> **For agentic workers:** you are `dev-codex` in Crew team `ibl-openidea`; `rev-agy` lints this plan and the coordinator names the code reviewer. Steps use checkbox (`- [ ]`) syntax. Within your session only one agent runs cargo at a time. Report to `pilot-bridge` with `crew send`, never in your chat.

**Goal:** on Windows, a first start that migrates the legacy profile shows a native progress dialog within a second, instead of no window for more than a minute. A second start during the copy brings that dialog to the front instead of looking dead. Nothing reads or creates the new profile before the copy is published.

**Architecture:** `migrate.rs` publishes a `Progress` record (phase and counters) while it copies, and tells a second start that it is waiting. A new `migration_feedback.rs` shows a `TaskDialogIndirect` from a helper thread that reads that record. `lib.rs` starts the feedback before the seed and finishes it after; everything else in the bootstrap keeps its place.

**Tech stack:** Rust (Tauri `openidea` crate), `windows-sys` 0.61 (already in `Cargo.lock`).

**Spec:** `docs/superpowers/specs/2026-10-31-migration-progress-design.md` at `41a4a4a8` (design), with the coordinator's decisions `DBA5C4`: option A with C as fallback if W3 fails, Windows only, option E (skip WebView caches) not in this tranche. Read it with `git show origin/fix/release-hardening:<path>`.

## Review Focus

1. The gate: in `run()`, `AppState::new`, the plugins and `create_main_window` still run only after `seed_profile_with_progress` returns. The feedback thread does no file access, opens no WebView and uses no Tauri API.
2. The lock: `try_lock` success keeps that lock and never calls `lock()` on the same handle; only `WouldBlock` leads to `WaitingForOtherStart` and the blocking `lock()`.
3. No delay without a migration: `finish()` interrupts the 500 ms wait, so a start with nothing to migrate is not slower.
4. The dialog cannot be dismissed while copying, closes itself at `Done`, and `finish()` never waits more than 2 s for its thread.
5. The journal, partials, renames, marker and existing tests behave exactly as before; the progress counters stay equal to the report, including after the counter reset at `migrate.rs:359`.

## 1. Context and goal

Defect D1 (design section 1). On the owner's PC the first start of 0.2.3-2 showed no window for about 94 s while `seed_profile` copied 18,895 files, 1.23 GB (owner-reported, not re-measured). The owner started the app again, and the second start reported `Resumed`. The bootstrap order is the cause: `seed_profile` runs at `lib.rs:50-58`, before logging (:59), the single-instance plugin (:84), `AppState::new` (:107) and `create_main_window` (:123), and `migrate.rs` gives no feedback (empty hook `:119-121`). That order is also the gate that keeps the new profile closed until it is published, so the fix adds feedback without moving it.

## 3. Solution design

As in the design, section 3 (a, b, c). Implementation points the design leaves open:

**a. `migrate.rs`.**
- `pub struct Progress` (`Default`, `Send + Sync`): `phase: AtomicU8` over `pub enum ProgressPhase { Checking, WaitingForOtherStart, Copying, Publishing, Done }`, `files: AtomicU64`, `bytes: AtomicU64`, `feedback_error: Mutex<Option<String>>`, `dialog_shown_ms: AtomicU64` (0 = never shown), `last_content: Mutex<String>` (the content text the dialog last set, for W3 and the log). Accessors return plain values.
- `pub fn seed_profile_with_progress(bases, from, to, progress: &Progress) -> SeedReport`. Internally one private `seed_run(bases, from, to, progress, hook, rename_delay)`; `seed_profile` and the private `seed_profile_with` (used by the existing tests) delegate to it with a throwaway `Progress`, so every existing test keeps its call.
- `Run` gets `progress: &Progress`. Phase changes:
  - `Copying` at `copy_phase` start (`:354`);
  - `Publishing` where the phase becomes `Renaming` (`:363`), and at the start of `publish` (`:370`) for a resumed rename;
  - `Done` in `seed_run` after `start()` returns, whatever the outcome, so the dialog also closes on `Failed` or `NotNeeded`.
- Counters: `copy_entry` adds to `files` and `bytes` next to `report.files_copied` and `report.bytes_copied` (`:485-486`, and the link branch at :499). Where `copy_phase` resets the report (`:359`), the counters reset too.
- Lock (`:265-274`): `match lock.try_lock()`. `Ok(())` keeps the lock. `Err(TryLockError::WouldBlock)` sets `WaitingForOtherStart`, then calls `lock.lock()?`. `Err(TryLockError::Error(e))` returns `Fault::Io(e)`, as `lock()?` does today.

**b. `src-tauri/src/migration_feedback.rs` (new).**
- `pub struct Feedback` and `pub fn start(progress: Arc<Progress>) -> Feedback`; `impl Feedback { pub fn finish(self) }`. On non-Windows both are no-ops: `start` spawns nothing, `finish` returns.
- Windows thread:
  1. `recv_timeout(500 ms)` on a channel that `finish()` signals. A signal, or a phase of `Done`, ends the thread without a dialog.
  2. `SetThreadDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` for this thread.
  3. Phase `WaitingForOtherStart`: look for the other start's dialog (`EnumWindows`; class `#32770` via `GetClassNameW`; exact title via `GetWindowTextW`; owner process from `GetWindowThreadProcessId`, opened with `PROCESS_QUERY_LIMITED_INFORMATION`, whose `QueryFullProcessImageNameW` equals `std::env::current_exe()`, compared case-insensitively). If found: `SetForegroundWindow`, record nothing as shown, and wait for the signal without a dialog. If not found: open its own dialog with the waiting text.
  4. Otherwise `TaskDialogIndirect` with `TDF_SHOW_MARQUEE_PROGRESS_BAR | TDF_CALLBACK_TIMER`, `TDCBF_OK_BUTTON`, no `TDF_ALLOW_DIALOG_CANCELLATION`. The callback:
     - `TDN_CREATED`: `TDM_SET_PROGRESS_BAR_MARQUEE(1, 0)` to start the marquee animation, `TDM_ENABLE_BUTTON(IDOK, 0)`, record the time;
     - `TDN_TIMER`: `TDM_SET_ELEMENT_TEXT(TDE_CONTENT, ..)` with the phase text and the counter line, and the same text stored in `last_content`; when the phase is `Done`, `TDM_ENABLE_BUTTON(IDOK, 1)` then `TDM_CLICK_BUTTON(IDOK)`;
     - `TDN_BUTTON_CLICKED`: `S_FALSE` while not `Done`, `S_OK` once `Done`.
  5. A failed `TaskDialogIndirect` (non-`S_OK` HRESULT) is stored in `feedback_error`; how long the dialog was shown goes into `dialog_shown_ms`.
- `finish()`: set a local done flag and signal the channel, then wait for the thread for at most 2 s (a second channel the thread signals on exit, `recv_timeout`); after 2 s detach it and store "feedback thread did not end" in `feedback_error`.
- Strings: `fn texts() -> &'static Texts`, chosen once from `GetUserDefaultUILanguage()`: primary language `LANG_ITALIAN` (0x10) gives Italian, `LANG_CHINESE` (0x04) gives Chinese, anything else English. Table in section 9's string list.

**c. `lib.rs`.** The block of design 3c, at the seed (`:49-58`). After the existing `report.log(..)` (:60-61): when `feedback_error` is set, `tracing::warn!`; when `dialog_shown_ms > 0`, `tracing::info!` with the duration. No other line of `run()` moves.
