## 1. Context and goal

On Windows the IDE kills only an agent's leader process; children stay alive, keep stdout/stderr open and lock the working directory (Antigravity probe, native Codex completion). Goal: implement the approved design [`docs/superpowers/specs/2026-10-31-process-tree-teardown-design.md`](../specs/2026-10-31-process-tree-teardown-design.md), sections 3 and 6, so that every agent process tree ends with its connection, for ACP, native Codex and native Claude.

## 3. Solution design

As in the design, section 3 (a, b, c), with the decisions of section 6:

- `ide-core`: a `ProcessTree` helper with `contain` (Windows `CREATE_NO_WINDOW | CREATE_SUSPENDED`, after `prepare()`), `adopt` (job `KILL_ON_JOB_CLOSE | BREAKAWAY_OK`, assign, resume every thread from a Toolhelp snapshot), `kill`, Drop closes the handle. Failure rules: assignment failure -> `warn`, `job = None`, still resume; zero threads resumed -> terminate and spawn error. Unix: no-op.
- `ProcessTree::kill` is synchronous and BLOCKING: with a job it calls `TerminateJobObject`; without one it runs `taskkill /T /F /PID` and waits for it to finish. The tree must be gone BEFORE the leader is killed, otherwise `start_kill` races `taskkill /T`. Async callers (`ide-jsonrpc` `supervise`, `claude/cli.rs` `Process::launch`) call it through `tokio::task::spawn_blocking(..).await` before `start_kill`.
- `ide-core` also exposes small Win32 probe helpers for tests in other crates, backed by its own `windows-sys`: for example `is_process_in_job(pid)`, `wait_for_pid_exit(pid, timeout)`, `terminate_pid(pid)` (doc-hidden, no behaviour of their own). This way `ide-jsonrpc` and `ide-agent` need no new dependency and `Cargo.lock` stays unchanged. Test temp dirs go under `std::env::temp_dir()` (no `tempfile` in `ide-jsonrpc`).
- `ide-jsonrpc`: private `spawn_inner(.., contain)`, new `pub Peer::spawn_contained`; `supervise` takes `Option<ProcessTree>`, calls `tree.kill()` in the kill branch before `start_kill`, and on natural exit after the bounded drain and before `mark_closed`. `Peer::spawn` and the LSP path unchanged.
- `ide-agent`: `lib.rs:305` and `native/codex/mod.rs:41` use `spawn_contained`; `native/claude/cli.rs` `Process::launch` contains after prepare, adopts after spawn, kills the tree before `start_kill`.
- `complete()` only: add `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never` to the child environment.
- LSP and DAP: unchanged (decision 2e).
